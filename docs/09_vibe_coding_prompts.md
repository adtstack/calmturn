# 09. Step-by-step Development Prompts - v4

이 문서는 v4 이후 작업을 에이전트나 개발자에게 맡길 때 사용할 짧은 프롬프트 모음이다. README와 docs 00-12를 먼저 읽고, v4 범위를 벗어나는 기능을 추가하지 않는다.

## 공통 규칙 프롬프트
```text
너는 Flutter 시니어 개발자다. 앱 이름은 `시계 (부부싸움 시리즈)`다.
README.md를 v4 기준으로 삼아라.
시작 화면은 이름, 첫 발언자, 각자 총 발언시간, 턴 제한만 보여준다.
실행 화면은 좌우 2분할 시계이며, 버튼은 일시정지와 종료만 둔다.
패널티/주의 표시는 실행 화면과 기본 기록 화면에 노출하지 않는다.
녹음, 마이크, 감정 분석, AI 요약, 클라우드 동기화는 추가하지 않는다.
변경 후 `./tool/check.sh`, `flutter test test/release_identity_test.dart`, `git diff --check`를 확인한다.
```

## Prompt 1 - 문서 정합성 확인
```text
README.md와 docs/*.md를 읽고 v4와 충돌하는 표현을 찾아줘.
특히 이전 버전의 복잡한 시작 흐름, 서로 다른 총 시간 중심 설명, 사용자-facing 패널티 문구, AI/녹음/클라우드 암시를 찾아라.
수정은 문서에만 제한하고, README의 v4 원칙을 기준으로 고쳐라.
```

## Prompt 2 - 시작 화면 회귀 방지
```text
시작 화면이 v4 단순 화면인지 확인해줘.
기본 이름은 남편/와이프, 총 시간 프리셋은 10/20/30/60분, 턴 프리셋은 1/3/5/10분이어야 한다.
오버타임과 패널티 세부 설정은 시작 화면에 직접 보이면 안 된다.
필요하면 위젯 테스트를 보강해줘.
```

## Prompt 3 - 실행 화면 회귀 방지
```text
TimerHomePage가 v4 실행 화면 요구사항을 만족하는지 확인해줘.
좌우 2분할, 전체 영역 탭으로 차례 넘기기, 현재 발언자 총 남은 시간에 따른 영역 폭 변화, 일시정지/종료 버튼만 유지해야 한다.
패널티/주의 문구가 노출되지 않는 테스트를 유지해줘.
```

## Prompt 4 - 마무리와 기록 검증
```text
WrapUpPage와 HistoryScreen을 v4 기록 요구사항 기준으로 점검해줘.
summaryText, tagsText, outcome이 저장되고, 달력에는 O/X가 최대 3개만 보여야 한다.
기존 로컬 기록에 새 필드가 없어도 읽히는 테스트를 유지해줘.
```

## Prompt 5 - Android 내부 테스트 준비
```text
docs/08_android_launch_checklist.md를 기준으로 Android 내부 테스트 준비 상태를 점검해줘.
release_identity_test가 요구하는 앱 이름, 패키지명, 아이콘, pubspec 버전 문구가 깨지면 안 된다.
실제 기기 QA와 서명된 AAB 준비 항목을 분리해서 보고해줘.
```

## Prompt 6 - 죽은 코드 정리
```text
v4에서 도달하지 않는 화면, 상태 필드, 위젯, 테스트 helper를 찾아 제거해줘.
기능 동작은 바꾸지 말고, analyzer와 관련 위젯 테스트로 검증해줘.
```

## Prompt 7 - 카피 점검
```text
앱 내 문구가 누가 옳은지 판단하거나 치료/상담을 암시하지 않는지 확인해줘.
추천 표현은 "대화 시계", "말할 시간", "기록", "잘 마무리됨", "아직 남음"이다.
피해야 할 표현은 "잘못", "벌점", "승패", "치료", "분석"이다.
```
