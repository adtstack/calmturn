# 06. Data Model & Timer Engine - v4

## 핵심 개념
v4의 핵심은 “현재 발언자에게만 시간이 흐른다”는 것이다. 각 참가자는 같은 총 발언시간을 받고, 한 번의 차례마다 턴 제한을 갖는다.

## 세션 설정
`SessionConfig`는 다음 값을 가진다.

- 참가자 A/B
- 각 참가자의 총 발언시간
- 턴 제한
- 첫 발언자
- 오버타임 설정
- 내부 패널티 기록 설정
- 알림 설정

기본 시작 화면은 같은 총 발언시간만 보여준다. 고급설정이나 저장된 과거 설정 때문에 참가자별 시간이 다를 수 있는 경우에도 검증 규칙은 가장 짧은 총 발언시간을 기준으로 한다.

## 타이머 상태
```text
runningNormal
runningOvertime
paused
needsExtension
finished
```

## 시간 계산
- Normal 상태에서는 현재 발언자의 총 남은 시간과 현재 턴 남은 시간이 줄어든다.
- 턴 시간이 0이 되면 설정에 따라 오버타임 또는 자동 휴식으로 이동한다.
- Overtime 상태에서도 현재 발언자의 총 남은 시간은 계속 줄어든다.
- 총 남은 시간이 0이 되면 세션은 추가 진행이 필요한 상태로 이동한다.
- Paused 상태에서는 총 시간, 턴 시간, 오버타임이 변하지 않는다.

## 패널티 데이터
- 패널티는 오버타임 기준 도달을 나타내는 내부 기록이다.
- v4 UI는 패널티/주의 표시를 사용자-facing 화면에 노출하지 않는다.
- 기존 기록 호환성을 위해 `penaltyCount`는 유지한다.
- 패널티는 승패나 잘못 판단에 사용하지 않는다.

## 기록 모델
`SessionRecord`는 타이머 스냅샷과 마무리 입력을 저장한다.

- `summaryText`: 총평
- `tagsText`: 해시태그
- `outcome`: 결과

`outcome` 값:

- `resolved`: 잘 마무리됨, 달력 표시 `O`
- `unresolved`: 아직 남음, 달력 표시 `X`

기존 기록에 새 필드가 없어도 읽을 수 있어야 한다.

## 테스트 케이스
- 현재 발언자 시간만 감소한다.
- 턴 제한 도달 시 오버타임으로 들어간다.
- 오버타임 중 총 시간이 계속 감소한다.
- 오버타임이 꺼지면 자동 휴식 상태에서 시간이 흐르지 않는다.
- 차례 넘기기는 활성 참가자와 턴 상태를 바꾼다.
- 총 시간이 끝나면 진행을 멈춘다.
- 기록은 새 필드와 기존 필드 모두 round-trip 한다.
