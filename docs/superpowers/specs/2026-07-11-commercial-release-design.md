# 시계 상업 배포 및 Pro 전환 설계

- 작성일: 2026-07-11
- 대상: Android / Google Play 첫 상업 배포
- 제품: `시계 (부부싸움 시리즈)` (`me.newlines.calmturn`)
- 상태: 사용자 승인 설계

## 1. 목적

현재 v4의 단순한 2인 대화 시계 경험을 유지하면서 무료 광고 모델과 저가 평생 Pro 상품을 추가하고, 상업 배포에 필요한 저장 안정성, 세션 복구, 결제 복원, 개인정보 고지, 백업 정책, 서명 빌드 검증을 완성한다.

이 설계는 핵심 타이머를 유료화하지 않는다. 무료 사용자는 대화를 시작하고, 차례를 넘기고, 마무리 기록을 저장하고, 전체 기록을 다시 볼 수 있어야 한다. Pro는 광고 제거와 서버가 필요 없는 편의 기능으로 차별화한다.

## 2. 확정된 제품 결정

### 2.1 수익 모델

- 무료 앱으로 배포한다.
- 무료판에는 배너 광고만 표시한다.
- Pro는 구독이 아닌 비소모성 평생 이용권 1회 구매다.
- Google Play 상품 ID는 `calmturn_pro_lifetime`으로 고정한다.
- 한국 가격은 `₩2,000`, 미국 기준 가격은 `US$2.00`으로 설정한다.
- 앱의 구매 화면에는 코드에 입력한 가격이 아니라 Google Play가 반환한 현지 통화 가격을 표시한다.
- 전면 광고, 앱 열기 광고, 보상형 광고는 사용하지 않는다.

### 2.2 무료 기능

- 현재의 시작 설정과 기본 시간 프리셋
- 2인 타이머, 차례 넘기기, 일시정지, 종료
- 오버타임과 현재 고급 시간 규칙
- 마무리 총평, 해시태그, 결과 저장
- 기록 달력, 일자별 목록, 상세 보기, 개별·전체 삭제
- 저장 안전성, 진행 세션 복구, 접근성, 개인정보 보호
- 기록 개수 제한 없음

### 2.3 Pro 기능

- 모든 광고 제거
- 최대 20개의 이름·시간·첫 발언자·알림 설정 프로필 저장
- 기록 검색
  - 참가자 이름
  - 총평
  - 해시태그
- 기록 필터
  - 날짜 범위
  - `잘 마무리됨` / `아직 남음`
  - 해시태그
- 월별 기록 보기와 중립적인 집계
  - 대화 횟수
  - 결과별 개수
  - 총 대화시간
- 전체 기록 JSON 내보내기와 JSON 가져오기
- 기록 CSV 내보내기
- 기본 테마 외의 시계 색상, 알림음, 진동 선택

Pro 집계는 사람의 잘못, 승패, 관계 건강도, 화해 가능성을 계산하거나 표현하지 않는다. 참가자별 발언시간도 사실값으로만 보여주며 점수화하지 않는다.

## 3. 광고 설계

### 3.1 광고 위치

무료 사용자에게만 다음 세 위치에서 광고를 표시한다.

1. 시작 화면
   - 제목과 설정 입력 영역 사이에 가운데 정렬된 중간 직사각형 광고 슬롯을 둔다.
   - 최대 크기는 `300x250`이며 작은 화면에서는 가용 폭 안에서 지원되는 광고 크기를 선택한다.
   - 설정 입력 요소와 광고 사이에 최소 24dp의 비클릭 여백과 시각적 구분을 둔다.
2. 일시정지 화면
   - 타이머를 먼저 일시정지한 뒤 화면 하단에 고정형 적응형 배너를 표시한다.
   - `재개`와 `종료` 조작부는 광고보다 위에 두고 최소 24dp를 분리한다.
3. 마무리 화면
   - 화면 하단에 고정형 적응형 배너를 표시한다.
   - 스크롤 가능한 기록 입력·액션 영역과 광고 슬롯을 분리한다.
   - `기록 저장`, `저장하지 않고 마치기`, `새 대화`, `기록 보기`와 광고 사이에 최소 24dp의 비클릭 여백과 구분선을 둔다.

### 3.2 광고 금지 위치

- 실행 중인 타이머 화면
- 종료 확인창과 삭제 확인창
- 텍스트 입력창이나 선택 컨트롤에 겹치는 위치
- 기록 달력, 일자별 목록, 기록 상세
- Pro 구매 흐름과 구매 완료 안내
- 앱 시작 로딩 화면

### 3.3 광고 로딩 규칙

- 광고 슬롯은 앱 콘텐츠를 덮지 않는다.
- 광고가 늦게 로드돼도 버튼이나 입력 영역의 위치가 갑자기 바뀌지 않도록 전용 슬롯을 먼저 확보한다.
- 동의 상태가 광고 요청을 허용하고 무료 사용자일 때만 광고를 요청한다.
- 광고 로딩 실패는 앱 사용, 일시정지, 기록 저장을 막지 않는다.
- Pro 권한이 활성화되는 즉시 기존 광고를 제거하고 이후 광고 요청을 중지한다.

## 4. 데이터 저장과 손상 방지

### 4.1 앱 데이터 경로

Android의 설정, 기록, 진행 세션은 모두 `Context.getFilesDir()` 아래의 전용 경로를 사용한다.

```text
filesDir/
  settings/app_settings.json
  records/session_records.json
  recovery/active_session.json
```

현재 상대 경로인 `.calmturn_session_records.json`은 새 기록의 영구 저장 위치로 사용하지 않는다. 앱 데이터 디렉터리 공급자를 설정과 기록이 공유하도록 만들고, Android가 아닌 플랫폼은 기존 플랫폼별 앱 지원 경로를 사용한다.

### 4.2 원자적 JSON 저장

설정, 기록, 진행 세션 저장은 공통 원자적 파일 저장 계층을 사용한다.

1. 같은 디렉터리의 임시 파일에 전체 JSON을 쓴다.
2. 파일 쓰기와 flush가 성공했는지 확인한다.
3. 기존 정상 원본을 `.bak`으로 교체한다.
4. 임시 파일을 원본 이름으로 원자적 교체한다.
5. 모든 쓰기 요청은 파일별 큐에서 직렬화한다.

각 JSON 루트에는 `schemaVersion`을 포함한다. 기록 파일의 초기 상업 버전 스키마는 `1`, 진행 세션 스키마는 `1`로 시작한다.

### 4.3 손상 복구

- 원본 파싱 또는 의미 검증이 실패하면 `.bak`을 읽는다.
- 백업이 정상이면 백업을 원본으로 복구하고 사용자에게 한 번만 복구 안내를 표시한다.
- 원본과 백업이 모두 잘못됐으면 어느 파일도 삭제하거나 빈 데이터로 덮어쓰지 않는다.
- 손상 파일은 `.corrupt-<UTC timestamp>` 이름으로 보존한다.
- 기록 화면은 복구 실패 상태와 지원 문의 경로를 보여준다.
- 저장 실패를 무시하고 성공처럼 표시하지 않는다.

### 4.4 기존 기록 마이그레이션

- 새 저장소에 기록이 없을 때만 기존 상대 경로 기록 파일을 탐색한다.
- 기존 파일이 유효하면 새 저장소에 원자적으로 복사하고 다시 읽어 동일성을 확인한다.
- 검증이 끝난 뒤에도 첫 상업 버전에서는 기존 파일을 삭제하지 않고 마이그레이션 마커만 저장한다.
- 기존 파일이 손상됐으면 새 빈 기록으로 덮어쓰지 않고 복구 실패 절차로 보낸다.

## 5. 진행 중 세션 복구

### 5.1 저장 시점

진행 세션 체크포인트에는 설정, 타이머 스냅샷, 시작 시각, 차례 시각 상태, 휴식 정보와 스키마 버전을 포함한다. 다음 시점에 저장한다.

- 세션 시작
- 차례 변경
- 일시정지와 재개
- 시간 연장
- 사용자 종료 요청
- 앱 생명주기가 비활성·백그라운드로 전환될 때
- 실행 중 5초 간격

### 5.2 백그라운드 동작

- 앱이 백그라운드로 가면 타이머를 자동 일시정지하고 즉시 저장한다.
- 백그라운드에 머문 시간을 어느 참가자의 발언시간에도 포함하지 않는다.
- 앱이 다시 활성화돼도 자동 재개하지 않는다.

### 5.3 재실행 복구 UX

유효한 진행 세션이 있으면 시작 화면 위에 `진행 중인 대화가 있어요` 카드를 표시한다.

- `이어하기`: 저장된 상태를 일시정지 화면으로 연다.
- `종료하고 마무리`: 현재 체크포인트로 세션을 종료하고 마무리 화면으로 이동한다.
- `삭제`: 확인창을 거쳐 복구 파일만 삭제한다.

복구 데이터가 손상됐으면 자동 삭제하지 않고 `복구할 수 없는 진행 기록이 있습니다`와 삭제·문의 선택지를 보여준다. 정상 마무리 또는 명시적 삭제가 끝나면 진행 세션 파일을 제거한다.

## 6. 구매, 복원과 오프라인 Pro

### 6.1 결제 구조

- Google Play Billing의 비소모성 1회 상품을 사용한다.
- 첫 상업 버전은 계정 서버와 자체 결제 백엔드를 만들지 않는 클라이언트 전용 구조다.
- 구매 상태가 `PURCHASED`일 때만 Pro를 부여한다.
- `PENDING` 상태에는 결제 보류 안내만 보여주고 Pro를 부여하지 않는다.
- 구매를 처리한 뒤 Google Play에 승인 결과를 보낸다.
- 구매 화면과 설정의 앱 정보 화면에서 같은 결제 서비스를 사용한다.

클라이언트 전용 구조는 서버 검증보다 변조와 환불 추적에 약하다. `₩2,000 / US$2.00`의 로컬 앱 첫 출시에서는 운영 복잡도를 줄이는 쪽을 선택한다. 불법 사용이나 환불 후 권한 유지가 유의미한 문제가 되면 구매 토큰 검증과 취소 알림을 처리하는 백엔드를 별도 후속 설계로 추가한다.

### 6.2 오프라인 권한 판정

- 마지막으로 Google Play에서 확인된 Pro 상태를 Android 보안 저장소에 캐시한다.
- 앱 시작 시 캐시된 Pro를 즉시 적용하고 광고를 만들지 않는다.
- 이후 Google Play 구매 목록을 비동기로 조회한다.
- 네트워크, Play Store, 일시적 Billing 오류는 기존 Pro를 해제하지 않는다.
- 성공한 구매 목록 조회에서 해당 상품이 없을 때만 로컬 Pro를 해제한다.
- 무료 상태에서 오프라인이면 구매 버튼을 비활성화하고 연결 안내를 표시한다.

### 6.3 구매 복원

- 설정의 앱 정보 화면에 `구매 복원` 버튼을 항상 제공한다.
- 복원은 현재 Google Play 계정의 구매 목록을 다시 조회한다.
- 복원 성공, 구매 없음, 연결 실패를 서로 다른 문구로 보여준다.
- 앱 재설치, 기기 변경, 오프라인 시작 후 온라인 복귀를 테스트한다.

## 7. 광고 동의와 개인정보

### 7.1 광고 원칙

- 전 세계에서 개인 맞춤이 아닌 광고를 기본 요청으로 사용한다.
- 앱은 참가자 이름, 대화시간 기록, 총평, 해시태그, 결과를 광고 SDK에 전달하지 않는다.
- 광고 SDK 초기화 전 Google UMP 동의 정보를 갱신한다.
- `canRequestAds`가 참일 때만 광고를 요청한다.
- 동의 정보 갱신 실패 시 기존 유효 동의가 광고 요청을 허용하는 경우만 광고를 요청하고, 그렇지 않으면 광고 없이 앱을 연다.
- 광고가 표시되지 않아도 무료 핵심 기능을 제한하지 않는다.
- 첫 상업 버전에는 Firebase Analytics, Crashlytics 또는 별도 사용자 행동 분석 SDK를 넣지 않는다. 충돌과 ANR은 Google Play Android vitals와 사전 출시 보고서로 확인한다.

### 7.2 개인정보 선택

- UMP가 개인정보 선택 진입점을 요구하는 지역에서는 앱 정보 화면에 `개인정보 및 광고 설정`을 표시한다.
- 사용자는 기존 동의를 다시 열고 변경하거나 철회할 수 있다.
- EEA, 영국, 스위스와 규제가 적용되는 미국 주의 테스트 지역을 UMP 디버그 설정으로 검증한다.
- 대상 고객은 성인으로 설정하며 아동 대상 앱이나 가족용 앱으로 등록하지 않는다.

### 7.3 Android 권한과 데이터 보안

광고 SDK 도입에 따라 release AndroidManifest의 기존 무네트워크 전제는 폐기한다.

- `INTERNET`과 `ACCESS_NETWORK_STATE`는 광고·결제에 필요한 허용 권한으로 관리한다.
- AdMob SDK가 병합하는 `com.google.android.gms.permission.AD_ID`는 광고 빈도 제한과 측정용 허용 권한으로 관리하되 앱 코드가 광고 ID를 직접 읽거나 대화 기록과 결합하지 않는다.
- Play 데이터 보안 답변에는 광고 SDK의 기기 ID 처리를 명시한다.
- 마이크, 녹음, 카메라, 위치, 연락처 권한은 계속 금지한다.
- 권한 자동 검증은 금지 목록과 허용 목록을 함께 검사하도록 바꾼다.
- Play 데이터 보안 답변은 앱 자체 기록과 광고 SDK 처리 데이터를 분리해서 작성한다.

개인정보처리방침은 `대화 기록은 앱 서버로 전송하지 않는다`와 `광고 제공자는 광고·기기·진단 데이터를 처리할 수 있다`를 동시에 명시해야 한다. 기존의 `서버 전송 데이터가 전혀 없다`는 표현은 광고 도입 이후 사용하지 않는다.

- 개인정보처리방침: `https://newlines.me/calmturn/privacy`
- 지원·FAQ: `https://newlines.me/calmturn/support`
- 문의 이메일: `calmturn@newlines.me`

릴리스 빌드는 세 값을 빌드 설정으로 주입하되 위 값을 제품 기본값으로 사용한다. 개인정보처리방침과 지원 페이지가 로그인, 지역 제한, 파일 다운로드 없이 HTTPS로 열리지 않으면 릴리스를 차단한다. 개인정보처리방침은 공개 HTML 페이지여야 하며 앱 내부에서도 같은 URL을 열 수 있어야 한다.

라이선스 화면은 Flutter 라이선스 레지스트리에 포함된 모든 런타임 패키지 이름과 라이선스 본문을 앱 안에서 검색·열람할 수 있게 한다.

## 9. Android 자동 백업

민감한 대화 기록을 운영체제 클라우드와 기기 간 전송에 자동 포함하지 않는다.

- 설정, 기록, 진행 세션, 로컬 Pro 캐시를 모두 자동 백업에서 제외한다.
- release AndroidManifest에 `android:allowBackup="false"`를 명시한다.
- Android 11 이하용 `fullBackupContent` 규칙과 Android 12 이상용 `dataExtractionRules`를 모두 제공한다.
- `cloud-backup`과 `device-transfer`에서 앱 데이터 도메인을 명시적으로 제외한다.
- `android:allowBackup` 값과 제조사별 동작 차이를 실제 기기와 `adb` 백업 도구로 확인한다.
- Pro 권한은 Google Play 구매 복원으로 되찾는다.
- 기록 이동은 Pro의 명시적인 JSON 내보내기·가져오기로만 수행한다.
- 앱 삭제나 기기 변경 시 내보내지 않은 기록이 사라질 수 있음을 앱 정보와 개인정보처리방침에 명시한다.

## 10. Pro 기록 이동

### 10.1 JSON 내보내기·가져오기

- JSON은 모든 기록 필드를 보존하는 공식 이동 형식이다.
- 파일 루트에 앱 식별자, 내보내기 형식 버전, 생성 시각, 기록 목록을 포함한다.
- 가져오기 전에 전체 파일을 파싱하고 모든 기록을 의미 검증한다.
- 하나라도 잘못된 기록이 있으면 아무 기록도 쓰지 않고 오류 위치를 안내한다.
- 같은 기록 ID는 가져온 값으로 덮어쓰지 않고 건너뛴다.
- 새 기록만 기존 기록에 합치며 결과 개수를 확인받은 뒤 원자적으로 저장한다.

### 10.2 CSV 내보내기

- CSV는 분석과 보관을 위한 단방향 형식이다.
- CSV 가져오기는 제공하지 않는다.
- 참가자 이름, 시각, 사용 시간, 결과, 총평, 해시태그를 올바르게 이스케이프한다.

공유 대상은 사용자가 Android 시스템 공유 시트에서 직접 고른다. 앱은 특정 클라우드나 서버로 자동 업로드하지 않는다.

## 11. 구성요소 경계

구현은 다음 책임 단위로 나눈다.

### `AppDataDirectory`

- 플랫폼별 앱 데이터 루트 경로만 제공한다.
- 설정, 기록, 복구 저장소는 이 인터페이스에 의존한다.

### `AtomicJsonFileStore`

- 임시 파일, flush, 백업, 교체, 손상 파일 보존, 쓰기 직렬화를 담당한다.
- 데이터 모델의 JSON 구조나 의미는 알지 못한다.

### `ActiveSessionStore`

- 진행 세션 스키마와 유효성 검증을 담당한다.
- 타이머 엔진을 직접 조작하지 않는다.

### `SessionRecoveryController`

- 생명주기 감시, 자동 일시정지, 체크포인트 저장, 복구 선택을 조정한다.
- UI는 복구 가능 상태와 사용자 선택만 전달받는다.

### `EntitlementService`

- 상품 조회, 구매, 승인, 복원, 오프라인 캐시를 담당한다.
- UI는 `free`, `pro`, `pending`, `unavailable` 상태만 소비한다.

### `ConsentAndAdsService`

- UMP 상태와 광고 요청 가능 여부를 관리한다.
- 무료이면서 동의가 허용된 경우에만 광고 슬롯에 광고를 공급한다.
- 화면은 광고 SDK를 직접 호출하지 않는다.

### `CommercialAppInfoScreen`

- Pro, 구매 복원, 개인정보, 광고 설정, 지원, 라이선스, 버전 진입점을 모은다.

### 플랫폼 범위

- 상업 배포와 결제·광고의 1차 대상은 Android다.
- Web 빌드는 개발 미리보기로 유지하고 결제·광고 서비스를 비활성 구현으로 연결한다.
- 상업 기능을 추가한 뒤에도 기존 `flutter build web --no-pub` 검증은 계속 통과해야 한다.
- iOS 배포와 App Store 결제는 이번 설계 범위 밖이다.

## 12. 오류 처리 원칙

| 오류 | 사용자 동작 | 앱 동작 |
|---|---|---|
| 기록 저장 실패 | 다시 시도 또는 저장 없이 나가기 | 성공으로 표시하지 않고 기존 파일 보존 |
| 기록 원본 손상 | 복구 결과 확인 | 백업 복구 또는 손상 파일 보존 |
| 체크포인트 실패 | 대화 계속 또는 종료 | 복구가 보장되지 않음을 한 번 안내 |
| Billing 연결 실패 | 다시 시도 | 기존 Pro를 해제하지 않음 |
| 구매 보류 | 결제 상태 확인 | Pro를 열지 않고 다음 실행에서 재조회 |
| 구매 승인 실패 | 자동 재시도 | 구매 토큰을 잃지 않고 재처리 |
| UMP 갱신 실패 | 앱 계속 사용 | 허용 근거가 없으면 광고 요청 안 함 |
| 광고 로딩 실패 | 앱 계속 사용 | 광고 슬롯 외 기능에 영향 없음 |
| 개인정보 URL 실패 | 출시 전 수정 | 릴리스 게이트 실패 |

## 14. 서명 AAB와 출시 게이트

### 14.1 서명

- 별도 업로드 키를 생성하고 저장소 밖의 안전한 위치에 보관한다.
- `android/key.properties`는 Git에 넣지 않는다.
- Google Play App Signing을 사용한다.
- 업로드 키 인증서 SHA-256 지문을 운영 기록에 보관한다.

### 14.2 출시 후보 명령과 검사

출시 후보는 다음을 모두 만족해야 한다.

1. `./tool/check.sh`
2. `git diff --check`
3. `flutter build appbundle --release`
4. AAB 패키지명, versionName, versionCode, target API, 권한 확인
5. 서명된 AAB의 인증서 확인
6. Play 내부 테스트 업로드 성공
7. Play 사전 출시 보고서의 충돌·ANR·접근성 문제 검토
8. 개인정보처리방침과 지원 URL 공개 접속 확인
9. Play 데이터 보안, 광고 포함 여부, 콘텐츠 등급 답변 검토
10. 실제 기기 QA 체크리스트 완료

2026-07-11 기준으로 2023-11-13 이후 생성된 개인 개발자 계정에는 최소 12명의 테스터가 14일 연속 참여하는 폐쇄 테스트 조건이 적용된다. 실제 제출 시 Play Console의 현재 요구사항을 다시 확인하고 충족한 뒤 프로덕션 접근을 신청한다.

## 17. 완료 기준

- 무료 사용자가 현재 핵심 대화 시계와 전체 기록을 계속 사용할 수 있다.
- 무료판 광고는 시작·일시정지·마무리의 승인된 슬롯에만 표시된다.
- Pro 구매·복원 후 오프라인에서도 광고가 없고 Pro 기능을 사용할 수 있다.
- Android 기록은 앱 데이터 절대 경로에 원자적으로 저장되고 손상 시 백업을 복구한다.
- 앱 강제 종료 후 진행 세션을 일시정지 상태로 복구할 수 있다.
- 광고 SDK가 처리하는 데이터와 로컬 대화 기록의 경계가 개인정보처리방침과 Play 데이터 보안 답변에 일치한다.
- Android 자동 백업과 기기 간 자동 전송에 앱 데이터가 포함되지 않는다.
- 서명된 AAB가 Play 내부 테스트에서 설치·구매·복원·광고 동의·세션 복구 시나리오를 통과한다.
