# 02. MVP Scope & Roadmap

## MVP 원칙
첫 버전은 “앱 하나로 관계 문제를 해결한다”가 아니라 “체스 시계처럼 대화 시간을 나누는 경험이 실제로 도움이 되는지 검증한다”에 집중한다.

## 반드시 포함할 기능
1. 두 명 이름 입력
2. 시간 프리셋 선택
3. 양쪽 동의 후 시작
4. 발언자별 카운트다운
5. 차례 넘기기
6. 일시정지/휴식
7. 종료 후 간단한 메모
8. 로컬 기록 저장
9. 기록 삭제

## MVP에서 제외할 기능
- 로그인
- 클라우드 동기화
- 음성 녹음
- 자동 음성 인식
- AI 감정 분석
- 공개 커뮤니티
- 상담사 연결
- 결제
- 3인 이상 모드
- 푸시 알림

## 단계별 개발 로드맵

### Phase 0 — 제품 확정
목표: 기능 범위를 고정하고 첫 UI 와이어프레임을 만든다.

산출물:
- PRD 확정
- 화면 목록 확정
- 타이머 모드 정의
- 앱 이름/톤 확정

완료 기준:
- “이 이상은 v1.0 이후”라고 말할 수 있는 제외 범위가 명확하다.

### Phase 1 — 타이머 엔진
목표: UI 없이도 동작하는 핵심 로직을 만든다.

구현:
- SessionState
- ParticipantTime
- start/pause/resume/switch/end
- 시간 종료 이벤트
- 단위 테스트

완료 기준:
- 테스트에서 발언자 전환과 일시정지가 정확히 동작한다.

### Phase 2 — 기본 UI
목표: 실제로 대화를 진행할 수 있는 화면을 만든다.

구현:
- 홈
- 세션 설정
- 동의 화면
- 타이머 화면
- 종료 화면

완료 기준:
- 휴대폰 하나를 테이블에 두고 2명이 사용할 수 있다.

### Phase 3 — 로컬 저장
목표: 세션 결과를 기기에 저장한다.

구현:
- 세션 기록 저장
- 기록 목록
- 기록 상세
- 삭제

완료 기준:
- 앱을 껐다 켜도 기록이 남는다.

### Phase 4 — 감성 UX와 안전 장치
목표: 차갑거나 통제적으로 느껴지지 않게 만든다.

구현:
- 휴식 문구
- 동의 문구
- 중단 안내
- 큰 글씨/VoiceOver 기초 대응
- 진단/치료 오해 방지 문구

완료 기준:
- 사용자가 “상대에게 강요하는 앱”으로 느끼지 않는다.

### Phase 5 — TestFlight
목표: 실제 부부/연인/팀 사용자에게 테스트한다.

구현:
- iOS 빌드
- TestFlight 업로드
- 피드백 폼
- 크래시/버그 체크

완료 기준:
- 최소 10쌍 또는 20명 이상이 실제 대화에서 사용하고 피드백을 남긴다.

### Phase 6 — App Store v1.0
목표: 공개 출시한다.

구현:
- App Store 메타데이터
- 스크린샷
- 개인정보 처리방침
- 지원 URL
- 심사 노트
- 최종 안정화

완료 기준:
- 앱스토어에 출시 가능하고, 첫 사용자에게 설명 없이도 사용된다.

## 4주 MVP 일정 예시

### 1주차
- 이름/브랜드 확정
- PRD 확정
- Flutter 프로젝트 생성
- 타이머 엔진 + 테스트

### 2주차
- 세션 설정 화면
- 동의 화면
- 타이머 화면
- 휴식/재개

### 3주차
- 종료 회고
- 로컬 저장
- 기록 목록/상세
- UI polish

### 4주차
- 접근성
- iOS 빌드
- TestFlight
- 사용자 피드백 수집

## v1.0 출시 전 의사결정
1. 앱 이름을 한국어 중심으로 갈지, 글로벌 영문명으로 갈지
2. 기록을 로컬에만 둘지, iCloud 동기화를 넣을지
3. 무료 앱으로 시작할지, 나중에 프리미엄 프리셋을 팔지
4. 앱을 “관계/라이프스타일”로 포지셔닝할지, “생산성/회의”로도 확장할지
5. AI 요약을 절대 MVP에 넣지 않을지, 실험만 할지
